# VISION.md テンプレート

以下のテンプレートを使って `docs/VISION.md` を作成する。ユーザーとの対話で各セクションを埋める。

```markdown
# プロダクトビジョン

## 一言で言うと
{このプロダクトは何か — 1〜2文で}

## 誰のために
{ターゲットユーザー。具体的なペルソナや役割}

## 何を解決するか
{ユーザーが抱えている課題。現状の不満や非効率}

## 成功の定義
{このプロダクトが成功したとき、何が起きているか}
- {定量的な指標があれば}
- {定性的なゴールでもOK}

## スコープ外（やらないこと）
{意図的に対象外とするもの。これがないとスコープが際限なく広がる}
- {例: モバイルアプリ対応}
- {例: マルチテナント}

## 技術的な制約・前提
{使用する技術スタック、既存システムとの統合、パフォーマンス要件など}
- {例: バックエンドはGo、フロントエンドはReact}
- {例: 既存のPostgreSQLデータベースを使用}

## 参考にするプロダクト・デザイン
{UIやUXの参考。「〜のような見た目」「〜のような操作感」}
```

## 記入のガイドライン

- **スコープ外** が最も重要。Claudeが自律的に判断するとき「これはやらない」が明確だと、不要な機能を追加しない。
- **参考にするプロダクト** があると、UIの自律判断の精度が大幅に上がる。
- 完璧でなくてよい。autopilot実行後のマイルストーンレビューで随時更新できる。

> **Note**: テンプレートは日本語で書かれていますが、プロジェクトの言語に合わせて英語で記入しても構いません。重要なのはClaudeが参照しやすい明確な記述であること。
